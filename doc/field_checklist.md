# Польовий чекліст — ttgo-lora-bench

Перевірки пари Base + Rover перед виходом у поле. Команди вводяться в консоль
(`pio device monitor -e base|rover`, або `POST /cmd` через Wi-Fi). Кожен пункт має
вимірюваний критерій: пункт пройдено лише тоді, коли критерій виконано буквально.

| # | Що перевіряємо | Як перевіряємо | Критерій проходження |
|---|---|---|---|
| 1 | Версія і роль прошивки | `version` на обох платах | однакова версія `X.Y.Z` без `-dirty` і без `-N-g…`; `role` = `base` / `rover` відповідно до наліпки на корпусі |
| 2 | Самотест при старті | увімкнути кожну плату; `post` | `POST ok, mask 0x00`; на OLED попап «Самотест OK»; у `/info` поле `post` = 0 |
| 3 | Живлення від акумулятора | від'єднати USB, увімкнути від АКБ; `post` (через Wi-Fi `/cmd`) | `power ok`, напруга ≥ 3700 мВ (заряд для польового дня); після 10 хв роботи в `SYNC` напруга впала не більше ніж на 100 мВ |
| 4 | Холодний старт ×20 | 20 разів повністю вимкнути живлення на ≥ 3 с і ввімкнути; після кожного разу `post` | 20 з 20: mask 0x00, `reset: power-on`; у `log all` немає записів `panic`, `wdt`, `brownout` |
| 5 | Порожній NVS (нова плата) | `pio run -t erase`, прошити, увімкнути; `config show` | старт без зависання: `load: fresh defaults`, усі параметри дефолтні, `POST` mask 0x00 (біт 5 config = ok) |
| 6 | Конфіг переживає обрив запису | `config stress 5000`, висмикнути живлення посеред запису, увімкнути; `config show` | `ota_url = http://stress.test/N`, де N — останній рядок `write N -> ok` перед обривом (або N+1); обидва слоти `ok`; потім `config reset` |
| 7 | Синхронізація | на одній платі «Синхронізація → почати», плати на відстані 1 м | обидві в `SYNC` за ≤ 30 с; однаковий session id в `/info` на обох |
| 8 | Стабільність зв'язку | лишити пару в `SYNC` на 15 хв | жодного виходу з `SYNC`; у CSV немає подій `SYNC_FAIL`; лічильник пропущених хартбітів не досягає 3 |
| 9 | Повний прохід вимірювання | «Вимірювання → почати» на будь-якій платі | `run : end how=0` на обох; session id +1 на обох (однаковий); у CSV 6 профілів × 8 пакетів з боку Rover на відстані 1 м (≥ 46 з 48 прийнято) |
| 10 | Робота без шлюзу (Wi-Fi недоступний) | вимкнути роутер, «Сервіс → Wi-Fi» | у лозі `wifi : no network reachable` не пізніше ніж через `wifi_timeout_s` (8 с) × кількість відомих мереж; після виходу з Wi-Fi плати знову синхронізуються (пункт 7), у `/info`/`log` немає перезавантажень |
| 11 | Вивантаження логів | роутер увімкнено, «Сервіс → Wi-Fi» на обох, переглядач `doc/LoRa_PC_viewer_makett.html` → «Завантажити» | обидві плати відповіли на `/info` і `/logs.csv`; кількість рядків MEAS у CSV збігається з прийнятими пакетами в пункті 9 |
| 12 | Вільне місце для логів | `/info` або переглядач | заповнення логу ≤ 50 % (TEST перестає логувати від 80 %); інакше вивантажити й «Сервіс → Стерти» |
| 13 | Мережа для вивантаження на місці | «Сервіс → Налаштувати Wi-Fi», телефон до `ttgo-lora-bench-XXXXXX` з паролем з OLED, додати мережу на 192.168.4.1 | мережа з'явилась у `wifi list`; після виходу «Сервіс → Передати по Wi-Fi» показує IP за ≤ 8 с |

Результат прогону фіксується в протоколі поля: дата, версія, плати (`device` з `version`),
пункти ✓/✗, для ✗ — що саме не виконалось.
