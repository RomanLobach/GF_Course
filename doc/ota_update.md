# Оновлення прошивки по Wi-Fi і відкат

**Мета.** Пристрій у полі сам ставить нову версію з GitHub Releases, не ламається від обриву
зв'язку посеред завантаження, а прошивка, яка не пройшла самотест після старту, автоматично
замінюється попередньою.

## Як влаштовано

Код — [src/Ota.h](../src/Ota.h), [src/Ota.cpp](../src/Ota.cpp).

1. **Маніфест.** `manifest.json` з адреси `ota_url` (за замовчуванням — ковзний реліз
   `hw6-latest`). Його публікує CI на кожен тег ([scripts/make_manifest.py](../scripts/make_manifest.py)):
   проєкт, версія і для кожної ролі — URL образу, розмір, SHA-256. Пристрій перевіряє проєкт,
   бере образ *своєї* ролі й порівнює версію: ставить лише новішу (`--force` — будь-яку).
2. **HTTPS.** Кореневі сертифікати вшиті в прошивку ([src/OtaRoots.h](../src/OtaRoots.h));
   GitHub переадресовує завантаження на `release-assets.githubusercontent.com`, переадресація
   проходиться. Для розробки дозволено й `http://` ([scripts/ota_server.py](../scripts/ota_server.py)).
3. **Запис.** Образ пишеться в *неактивний* розділ (`app0`/`app1`) шматками по 4 КБ через
   `Update.write`, паралельно рахуються SHA-256 і розмір. Розділ завантаження перемикається
   (`Update.end`) лише якщо обидва збіглися. Обрив, тайм-аут, скасування чи хибний хеш —
   `Update.abort()`, і пристрій лишається на поточній прошивці.
4. **Не блокує протокол.** TLS і HTTP виконуються в окремій задачі FreeRTOS; основний цикл лише
   запускає її й читає прогрес. Оновлення можливе тільки в `IDLE`, радіо на цей час на паузі.
5. **Відкат.** Щойно встановлена прошивка стартує в стані «на перевірці». Після самотесту вона
   підтверджується, лише якщо POST = 0 і роль збігається з тією, з якою плату прошили вперше
   (зберігається в NVS). Інакше прошивка позначається недійсною, і завантажувач повертає
   попередню; після повернення в системному лозі — `update in appN rejected, rolled back`.
   Якщо нова прошивка зависне чи впаде до підтвердження, відкат так само робить завантажувач.
   Прошивка кабелем під перевірку не потрапляє.

Запуск: меню «Сервіс → Оновити прошивку» (прогрес на OLED, натискання — скасувати) або консоль
`ota check`, `ota update [--force]`, `ota status`, `ota cancel` (також через `POST /cmd`).

## Перевірка на платі (Rover, 2026-10-04)

Повні логи — [logs/rover-ota-local-0.3.0.txt](logs/rover-ota-local-0.3.0.txt). Локальний сервер:
`python scripts/ota_server.py --version 9.9.9`, `config set ota_url http://<ПК>:8000/manifest.json`.

| Сценарій | Що зроблено | Результат |
|---|---|---|
| Перевірка з GitHub | `ota check` на `hw6-latest` (0.2.0) по HTTPS | маніфест за ~6 с, `up to date` — нічого не ставиться |
| Встановлення | `ota update`, образ 1 136 624 Б | 8 с завантаження, перезапуск у `app1`, `new image confirmed in app1` |
| Відкат | образ з `-D FW_FORCE_POST_FAIL` як 9.9.10 | старт у `app0`, POST `0x80` → `rolling back` → старт у `app1`, POST `0x00`, `rejected, rolled back` |
| Обрив зв'язку | сервер зупинено посеред завантаження | `connection lost at 649468 B`, запис скасовано, пристрій на `app1` |
| З меню | «Сервіс → Оновити прошивку» | смужка прогресу, `installed 9.9.11` → `new image confirmed in app0` |
| Скасування з меню | натискання посеред завантаження | `cancelled`, попап «Оновлення не вдалося: скасовано», пристрій на поточній прошивці |

## Висновки

- Оновлення атомарне: до `Update.end` активний розділ не змінюється, тож обрив, скасування чи
  пошкоджений образ ніколи не залишають плату без робочої прошивки.
- Прошивка, що не пройшла самотест, сама відкочується за один перезапуск (~1 с), без кабелю.
- Під час перевірки знайдено хибний збій самотесту `oled` (~1 старт із 4): одразу після
  швидкого скидання дисплей ще не відповідав по I2C. Такий старт відкотив би справну
  прошивку. Тепер самотест робить до 5 спроб з паузою 20 мс; після виправлення 8 з 8 стартів
  без збою.
