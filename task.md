Мета завдання — навчитися знаходити причину падіння прошивки: отримати інформацію про crash, знайти місце помилки за допомогою backtrace та навчитися працювати з інструментами дебагу. У production-розробці .elf файл використовується саме для аналізу таких ситуацій — він містить символи й адреси, необхідні для декодування помилок.

Основне завдання

1. Спровокуйте crash пристрою

Створіть ситуацію, у якій ваша прошивка аварійно завершується.

Наприклад:

зробіть ділення на нуль;викличте некоректний доступ до пам’яті;створіть іншу помилку, яка призведе до перезавантаження пристрою.

Після падіння пристрій має вивести інформацію про помилку через Serial Monitor.



2. Отримайте та проаналізуйте backtrace

Після crash знайдіть у логах:

причину помилки;регістри CPU;Backtrace — стек викликів, який показує шлях виконання програми до моменту падіння.

Збережіть отриманий лог.



3. Декодуйте backtrace

Використайте одне з розширень для розшифрування адрес у зрозумілий код:

Варіанти:

dankeboy36/esp-exception-decoder (рекомендований варіант)me-no-dev/EspExceptionDecoder (старіший варіант)

Після декодування потрібно отримати:

файл, у якому сталася помилка;номер рядка;функцію, яка призвела до crash.



Додаткове завдання ⭐

Виконайте один або обидва пункти.

1. Прочитати поточний Partition Table програмно

Напишіть код, який:

отримує інформацію про поточний partition table;виводить список розділів у Serial Monitor.

У виводі мають бути присутні:

назва розділу;тип;підтип;адреса;розмір.



2. Прочитати розділ partitions на низькому рівні

Використовуючи низькорівневі функції ESP32:

знайдіть розділ partitions;прочитайте його бінарний вміст;виведіть отримані дані у консоль.



Що потрібно здати

Посилання на репозиторій із кодом.Лог із Serial Monitor після crash.Результат декодування backtrace:причина помилки;файл;номер рядка.причина помилки;файл;номер рядка.Скриншот або текстовий вивід виконання додаткового завдання ⭐ (якщо виконували).



Критерії виконання

✅ Прошивка навмисно падає та генерує crash.✅ Отримано та збережено backtrace.✅ Backtrace успішно декодовано через одне з розширень.✅ Визначено точне місце помилки у коді.⭐ Додатково: отримано інформацію про partition table або прочитано бінарні дані розділу.

У результаті ви маєте отримати навичку, яка використовується під час реальної експлуатації пристроїв: не просто побачити, що плата перезавантажилась, а зрозуміти чому саме це сталося.
